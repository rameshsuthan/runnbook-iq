# RunbookIQ Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the first real three-document cited answer through LangGraph, then complete the local Phase 1 baseline.

**Architecture:** Explicit ingestion writes canonical chunks and a dedicated Pinecone namespace. A sequential LangGraph workflow prepares the original query, retrieves/selects evidence, generates through Gemini or abstains, and validates citation IDs. CLI, UI and evaluation share these boundaries.

**Tech Stack:** Python 3.12, uv, Pydantic, LangGraph, Pinecone integrated `llama-text-embed-v2`, native LangChain Gemini integration, SQLite, pytest, Streamlit.

**Spec:** `docs/superpowers/specs/2026-10-18-phase-1-design.md` — user approved 2026-10-18. Also read `RunbookIQ-Codex-Handoff.md`.

**Status:** Prepared for plan review. All checkboxes below describe future work, not completed verification. Recommend native execution to keep these closely dependent tasks in one context; use the required final independent review. No product implementation has started.

## Global Constraints

- Target Python 3.12 in a project-local virtual environment; resolve and lock actual dependencies during setup.
- The user selected **Gemini** for Phase 1. Nebius remains the intended second provider for Phase 2.
- The cross-phase estimated paid-usage guard is **USD 3**, with a **USD 1–2 target**.
- Default to verified free access and no paid fallback.
- SDK and application generation retries are disabled in Phase 1, so an ordinary uncached supported question makes at most one chat call.
- Ingestion is an explicit command, never a side effect of application startup or a question.
- Do not silently truncate documents or queries.
- Configuration flags for hybrid retrieval, reranking, multi-query and repair must raise a clear unsupported-feature error if enabled now.
- Ordinary tests use fakes and make no network or paid calls.
- No live-system access, remediation, deployment, authentication, or autonomous loops.

## Review Focus

1. Crash or concurrent CLI/UI request near the budget limit: reservations survive and cannot overspend the local guard (Task 3).
2. Interrupted reingestion or stale remote records: requests cannot mix corpus versions or delete another project's records (Task 4).
3. Unicode, fenced Markdown and oversized individual blocks: token bounds preserve content or fail visibly (Task 2).
4. Nonempty but irrelevant/adversarial evidence: generation may abstain; document instructions never override the answer contract (Tasks 5 and 8).
5. Provider truncation, missing usage and UI reruns: no repair loop, invented zero-cost report, or duplicate generation (Tasks 3, 5 and 7).

| Files | Responsibility |
|---|---|
| `pyproject.toml`, `uv.lock`, `.python-version`, `.gitignore`, `.env.example`, `config.yaml` | Reproducible runtime, safe defaults and secret exclusion |
| `src/runbook_iq/config.py`, `schemas.py` | Validated settings, canonical records and shared result types |

| `ingestion.py`, `retrieval.py` | Project-scoped Pinecone synchronization and normalized search |
| `budget.py`, `providers.py`, `generation.py`, `cache.py` | Durable usage guard, Gemini adapter, answer validation and versioned cache |

| `app.py` | Streamlit form and inspectable source passages |
| `data/docs/`, `eval/questions.json`, `eval/results/` | Original synthetic sources, frozen expectations and sanitized actual runs |
| `tests/` | Offline boundary/behavior tests and network-denial fixture |

Create modules when their task uses them. `src/runbook_iq/__init__.py` is the package marker. Generated chunks/manifests live in `data/processed/`; ignored ledgers/cache live in `.runbook_iq/`. Credentials are explicit environment inputs, not fields in serializable settings. Never stage whole directories containing secrets without inspecting the file list.

Each task ends by recording actual commands/results and next action in `PROGRESS.md`, updating lasting decisions in `PROJECT_CONTEXT.md`, and committing its explicit changed files. Do not invent a Git identity if none is configured. Resolve sandbox restrictions narrowly; do not erase existing work.
