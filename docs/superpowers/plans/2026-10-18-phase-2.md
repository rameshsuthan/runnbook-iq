# RunbookIQ Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Native execution is already selected. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add inspectable hybrid retrieval, reranking, safe query expansion, bounded repair and provider portability while preserving the runnable Phase 1 baseline.

**Architecture:** Extend the current canonical-record pipeline and sequential LangGraph nodes. Share retrieval/selection between answer and retrieval-only runs, retain separate retrieval scores and operation usage, and add only one explicit repair cycle. Default switches stay off; Gemini remains active while Nebius access is unavailable.

**Tech Stack:** Existing Python 3.12, Pydantic, LangGraph, native LangChain Gemini, Pinecone SDK, SQLite, Streamlit and pytest. BM25/RRF use the Python standard library; an OpenAI-compatible client dependency is introduced only with the Nebius adapter.

**Spec:** [Approved Phase 2 design](../specs/2026-10-18-phase-2-design.md).

Status: implementation plan approved; Native execution in progress.

## Global Constraints

- Keep every feature independently switchable and all switches off by default.
- BM25 reads the *active* canonical snapshot used by Pinecone, not a fresh independent split of Markdown.
- Use deterministic BM25 with positive IDF, `k1=1.5`, `b=0.75`.
- RRF constant 60; at most three queries, five hits per query/method, 15 fused candidates and five final evidence chunks.
- Use `bge-reranker-v2-m3`, original question, one text field and `truncate=NONE`.
- Reuse the existing persistent USD 3 ledger across branches, phases and restarts.
- Promotional credits count at listed estimated consumption; paid fallback remains disabled; SDK retries remain zero.
- Maximum chat attempts per request: one expansion + one answer + one repair = three.
- Existing corpus/questions/results and the v3 answer prompt remain frozen for retrieval comparisons.
- Secrets stay local; ordinary tests deny network access. Never print SDK exceptions, headers, credentials or rejected output by default.
- Preserve `origin/phase-1` at `e15502e`; work on `phase-2`. User-owned untracked files stay untouched.
- Native implementation with one independent whole-branch review at the end; do not dispatch task-by-task agents.

## Review Focus

1. Corpus changes during multi-query retrieval: reject the whole batch, never mix versions (Task 2).
2. Identifier punctuation, repeated tokens and filtered-out top hits: preserve exact tokens and find eligible hits before top-k (Task 1).
3. Timeout after a chargeable invocation and partial token metadata: retain reservations and expose incomplete totals (Task 3).
4. Cache reuse after expansion/configuration changes: use the current run's operations, evidence and effective configuration (Tasks 2, 5, 6).
5. Malformed reranker indices or repeated invalid model output: fail visibly without corrupting evidence or looping (Tasks 4, 6).
